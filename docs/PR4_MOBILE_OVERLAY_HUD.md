# PR #4 モバイルオーバーレイ・HUD整理

## 目的

PR #3で整理した「操作・学習・技術」の3タブと状態保持を維持したまま、狭い画面で3Dモデルを観察しやすいHUDとボトムシートへ再構成する。機構と描画の基準には触れず、常設オーバーレイの占有面積と、モバイルで開いたパネルの高さだけを縮小する。

## 基準

基準コミットは`368ac3d447627773605cbc8146d98779fae6eae3`（v3.12.0 / PR #3 UIアーキテクチャ整理）である。作業ブランチは`refactor/mobile-overlay-hud`、GitHubが割り当てたDraft PRは[#4](https://github.com/showhey04-oss/mechanical-watch-3d/pull/4)である。

## HUD状態

右上の部品情報`#info`は初回起動時に`hidden`かつ`aria-hidden="true"`とし、レイアウト領域を占有しない。実際の部品選択時だけ表示して`aria-hidden="false"`へ切り替え、背景タップ、表示条件による選択無効化、リセットでは再び非表示にする。

部品名と説明はPR #3から継承した`partsInfo`と`setPartInfo()`系統で右上HUDと学習タブへ同時反映する。説明文を別のデータへ複製していない。

## バージョン表示

3Dキャンバス右上の常設バージョンピルを撤去した。モデル名、`v3.13.0`、`基準：PR #3 UIアーキテクチャ整理`は学習タブ内の「モデル情報」へ移動した。HTMLの`<title>`とパネル表示は実行時定数`APP_VERSION`を共有する。

## ハンバーガーとARIA

文字付きのメニューピルを、CSSで描く低コントラストの3本線へ置き換えた。実機レビュー追補ではPC・モバイル共通で通常時の外枠、影、常時背景を撤去した。ボタンの実操作領域は44×44 CSS pxで、safe areaを考慮し、`focus-visible`の輪郭だけは維持する。

- `aria-controls="panel"`で対象を明示
- 開閉状態と`aria-expanded`を同期
- 状態に応じて`メニューを開く`／`メニューを閉じる`へ`aria-label`を同期
- pointer、Enter、Spaceの実入力で同じ開閉処理を使用
- デスクトップの折りたたみとモバイルの開閉で同じ状態同期関数を使用
- デスクトップでは展開時の左端387pxから折りたたみ時の10pxへ追従し、再展開時は387pxへ復帰
- 追従位置は`data-panel-expanded`から決める絶対配置であり、`transform`の増分や累積値を使用しない
- 1280×720→390×844→1280×720の動的resizeでも、モバイル移行時の既存自動close、手動再open、デスクトップ復帰の状態とARIAが一致し、位置は387→10→387pxとなる

## 時刻入力の診断と修正

実機レビュー時点の実装を、iOS相当の`input[type="time"]`で`HH:mm`／`HH:mm:ss`を入力し、`input`、`change`、`blur`、pointer／touch相当ボタン`click`の順序、`watchTimeSec`、表示時刻、3針角、Live Sync、Visual Viewportを記録して診断した。原因は次の2点だった。

1. 旧実装は単一の`applyTimeInput()`を「入力時刻に設定」ボタンの`click`だけへ結線しており、iOSの時刻pickerが確定時に発火する`change`では時計へ適用していなかった。
2. 位置2では既存の描画ループから`setEditorTime()`が呼ばれ、フォーカス中の時刻入力も表示中の時計時刻で毎フレーム書き戻し得た。このため、pickerで選択した値が確定前に旧値へ戻る経路があった。

Visual Viewportの処理は、フォーカスした入力をスクロール領域内へ移すだけで、値の変更、イベント抑止、ボタンclickの阻害はなく、原因ではなかった。また、旧Live Sync UIは入力と適用ボタンをdisabledにしていたため、同期中の手動上書き経路が成立していなかった。

修正後は、厳密な`HH:mm`／`HH:mm:ss`パーサーと1本の時刻適用関数を維持し、`change`を確定経路、`blur`とボタン`click`をフォールバックとして接続した。編集revisionで同一入力の二重適用を防ぎ、フォーカス中は`setEditorTime()`の書き戻しを止める。手動適用に成功した場合だけLive Syncを解除し、`timeMode`、チェック状態、内部`liveSync`を同時に更新する。空文字、非数、範囲外は時計状態を変更しない。

`10:08:30 → 13:37:42`と`10:08 → 13:37`の双方で、入力値、表示時刻、`watchTimeSec`、時・分・秒針角、管／軸との拘束が一致した。位置1／位置2を往復しても旧時刻へ戻らず、Live Sync ONからの手動適用は1回だけ反映されて同期OFFへ移行した。

## 時刻入力レイアウト

時刻グリッドと子要素へ`min-width: 0`、時刻入力へ`width: 100%`と`max-width: 100%`を設定し、420px以下では1列へ切り替えた。390×844、393×852、375×667の全てで入力右端が本文右端以内、document／timeGridの横オーバーフローが0になった。Visual Viewport 390×520相当でも入力全体をスクロール領域内へ維持した。

## トグルカード

Live Sync 1件、構造表示3件、表示グループ9件、技術診断2件、振幅自動設定1件の計16チェックボックスを同じトグルカードへ統一した。既存の`input`、ID、`data-group`、初期checked、change処理は維持し、inputは`display:none`にせずvisually-hidden方式とした。

- 各カードは高さ44px以上、`justify-content:flex-start`、インジケータと文章のgap 9px
- ONは弱い金色、OFFは暗いグレー、disabledは操作不可が明確な別のグレー
- 全16カードでtouch相当pointerとラベル全体の操作、native inputのキーボードフォーカス／Space activation、元状態への復帰を確認。Spaceは`keydown`の既定動作を抑止して同じinputの`click`へ1回だけ流し、環境差による未反映や二重反転を防ぐ
- `checked`／disabledからカード表示を同期し、既存change処理を維持したままモデル状態との一致を診断で確認
- 長文を折り返し、375px幅でも横オーバーフロー0

## モバイルボトムシート

899px以下では、開いたパネルを`min(56dvh, 620px)`へ制限した。パネルは下端固定、ハンドルは固定高、`#body`だけが残り高さを使うスクロールコンテナであり、タブバーは本文スクロール中もsticky表示される。閉じた状態はハンドルだけを残す。

`VisualViewport`の変化はイベント時だけ処理し、フォーカス中のパネル入力が表示範囲外へ隠れた場合に本文をスクロールする。animation loopへのDOM更新は追加していない。

## 上部3D領域の操作

パネルを開いた状態でも上部キャンバスはDOMで覆われず、実pointerイベントによる1本指回転、2点pointerによるズーム・パン、部品選択、背景タップによる選択解除が成立する。パネル外の操作ではパネルを閉じず、パネルを閉じた後も同じ方向へ3D回転を継続できる。

位置1の巻上げと位置2の時刻合わせは、パネルを開いたまま上部3D領域で観察した。秒停止と位置1復帰後の運転再開も既存回帰試験に含めた。

## 状態不変性

HUD開閉、部品説明表示、タブ切替だけでは、モデルWorld姿勢、カメラ状態、機構角、りゅうず位置、表示時刻、主ゼンマイ残量、選択対象を変更しない。選択は背景タップ、リセット、または表示条件によって対象が無効になった場合に解除する。

## 変更しない範囲

基準コミットから次を変更していない。

- 主輪列、日の裏輪列、巻上げ輪列、機構グラフ
- 巻上げ、時刻合わせ、秒停止、A.7キーレス絶対配置
- Three.js Object3Dの座標、回転比、位相、Geometry
- ArcballControls、カメラプリセット、平滑化
- ライト、影、露出、tone mapping、材質、背景テーマ
- 構造透過方式、適応DPR、Raycaster候補選定、animation loop
- 既存3タブの情報配置、状態保持、URLパラメータの意味

モバイル実機の暗部・影・露出差はIssue #2へコメントとして追記し、本PRではレンダリングを変更していない。Issue #2はOpenのまま維持する。
